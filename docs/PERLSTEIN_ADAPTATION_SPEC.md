# אפיון התאמה: מערכת קופמן → פרלשטיין משכנתאות

> **סטטוס:** טיוטה ראשונה לדיון (Draft v0.1)
> **מקורות:** ‎3 קבצים שהתקבלו מהמשרד (14.8.2026) — "אקסל משימות" (גיליון העבודה הראשי),
> "משימות ונהלים בתיק" (נהלי עבודה + זמני יעד), סקריפט Google Apps Script של לוח המשימות,
> ורשימת בקשות מצ'אט WhatsApp.

---

## 1. רקע ואסטרטגיה

משרד פרלשטיין מנהל היום את כל התיקים בגיליון Google Sheets אחד + סקריפט אוטומציה
שנבנה בהתאמה אישית. ~68 תיקים פעילים בעמודות. שני מטפלים פעילים בגיליון
(מזוהים בסקריפט כ"שמעון" ו"מנחם").

**הגישה המוסכמת (עלתה גם בצ'אט מצדם):** לא בונים "מערכת חלומות" מאפס.

- **שלב א' — מעבר למערכת מובנית** על בסיס הפלטפורמה הקיימת (קופמן), עם התאמות
  שמשמרות את הרגלי העבודה הקיימים שלהם. המטרה: להרגיל את המשרד לתעד ולעבוד מובנה.
- **שלב ב' — שכבת AI** (המלצות שמאי, ניתוחים, אוטומציות). שלב ב' תלוי בדאטה
  שנצבר בשלב א' — בלי תיעוד מובנה אין על מה להריץ AI.

## 2. איך המשרד עובד היום (ניתוח הקבצים)

### 2.1 הגיליון הראשי — עמודה לכל תיק

מבנה עמודת תיק (שורות קבועות):

| שורה | תוכן | הערות |
|---|---|---|
| 1 | בנק + סניף | לפעמים עיר/מקור ("נתניה", "הלוואות קבלן") |
| 2 | שם לקוח | מפתח הזיהוי היחיד |
| 3 | טלפונים / מייל | טקסט חופשי, לרוב שני מספרים (בעל+אישה) |
| 4 | תאריך יעד | לא עקבי — לפעמים טלפון או טקסט אחר |
| 5 | מטרת הלוואה + עיר | רכישה / שיפוצים / מיחזור |
| 6 | סכום רכישה | |
| 7 | סכום הלוואה | |
| 8 | שווי נכס | |
| 9 | הכנסה נדרשת | מחושב ידנית |
| 10–14 | הכנסות (עד 5) | טקסט חופשי: "תלוש אשה 11100", "עוסק בעל 3300", "תצהיר 8000" |
| 15–17 | התחייבויות (עד 3) | "החזר משכנתא 5500", "החזר הלוואת רכב 1900" |
| 18 | נכסים | |
| 19–46 | משימות פתוחות | טקסט חופשי, סימון נקודות (ר' 2.2) |
| 47 | הפניה | שם המפנה |
| 48+ | תשלומים | זוגות סכום/תאריך; הסקריפט חותם תאריך אוטומטית עם הזנת סכום |

**תובנה חשובה:** בפועל השורות "זולגות" — משימות מופיעות בשורות הכספיות ולהפך.
המבנה חצי-מובנה בלבד, וזה ישפיע על המיגרציה (ר' סעיף 6).

### 2.2 שיטת הנקודות — משימות + שיוך + דחיפות

טקסט משימה בעמודת תיק מסתיים ב-1–4 נקודות:

| נקודות | משמעות | צבע בגיליון |
|---|---|---|
| `.` | משימה של שמעון | כחול |
| `..` | משימה של מנחם | צהוב |
| `...` | דחוף — שמעון | אדום |
| `....` | דחוף — מנחם | אדום |

הסקריפט מרכז את הכל ללוח משימות (עמודות B–E): "לקוח – משימה", ממוין
**דחוף → תאריך יעד → סדר תיקים**, עם צ'קבוקס שסוגר את המשימה במקור.
בזמן צילום המצב: **44 משימות פתוחות לשמעון, 10 למנחם.**

זה בעצם: משימה = תיק + טקסט + משויך + דחיפות + תאריך יעד (ברמת התיק).
בדיוק מודל ה-Tasks הקיים במערכת. **הרגל העבודה שצריך לשמר: מסך "המשימות שלי"
מרוכז וממוין, וסימון ✓ מהיר.**

### 2.3 קובץ הנהלים — תהליך העבודה + SLA

קובץ "משימות ונהלים בתיק" מכיל ~40 שלבי תהליך עם זמן יעד לכל שלב. דוגמאות:

- מענה ללקוח — תוך יום
- מייל דרישת מסמכים — באותו יום
- בניית תיק — 3 ימי עסקים מקבלת מסמכים
- הגשה — תוך יום מהשלמת מסמכים
- בחירת שמאי — עד יומיים מקבלת ההפניה
- מסמכי בטחונות לעו"ד — תוך יום מקבלתם מהבנק
- מייל שכ"ט — יום אחרי ביצוע

**זה נכס:** תהליך העבודה שלהם כבר מקודד. מתרגם ישירות לתבניות משימות
אוטומטיות פר שלב + התראות SLA (מודול ה-SLA הקיים).

### 2.4 רשימת הבקשות מהצ'אט

1. ארכיון לתיקים שבוצעו
2. רשימת שמאים לכל בנק + טלפונים
3. **המלצת שמאי לפי תיקים קודמים** — ניתוח לפי בנק/עסקה, דירוג שווי/לו"ז
4. משרדי עו"ד / חברות נדל"ן — פרטי קשר לשימוש חוזר
5. שכ"ט
6. מעקב הפניות: מי הפנה, האם מגיעים דמי הפנייה וכמה
7. פרטי סניפי בנק ובנקאים/יות (רשימה נוכחית: מזרחי הילני המלכה / אגריפס /
   חשמונאים, מרכנתיל רוממה, פועלים בית שמש, דיסקונט יפו, קרדיטו, מימון ישיר, פמה)

## 3. מיפוי מול המערכת הקיימת

### 3.1 קיים ומכסה כמעט אחד-לאחד

| צורך של פרלשטיין | מודול קיים |
|---|---|
| תיק + לווים + בנקים + סטטוס | `cases`, `borrowers`, `case-banks` |
| הכנסות מובנות (תלוש/עוסק/תצהיר, בעל/אישה) | `incomes` (`borrower_incomes` + טבלת סוגים) |
| התחייבויות | `obligations` |
| משימות עם משויך, דחיפות, תאריך יעד | `tasks` |
| גביית שכ"ט בתשלומים + תאריכים | `collections` |
| התראות זמני שלב | `sla` + `notifications` |
| ארכיון תיקים שבוצעו | סטטוס "בוצע" + סינון (קיים) |
| לידים לפני תיק | `leads`, `intake` |
| הרשאות לפי תפקיד + שדות מנהל בלבד | `permissions`, `settings` |
| מסמכים + Drive | `documents`, `integrations` |

### 3.2 קיים אך דורש התאמה

- **סטטוסים:** ‎12 השלבים הקיימים מכסים את התהליך של פרלשטיין. לוודא מולם
  שהניסוחים מדברים אליהם, או להפוך את שמות הסטטוסים לקונפיגורציה פר-משרד.
- **תבניות משימות פר שלב:** להזין את ~40 הנהלים כתבניות — מעבר שלב מייצר
  אוטומטית את המשימות של השלב עם תאריכי יעד לפי ה-SLA שהוגדר.
- **מסך "המשימות שלי":** לוודא שחוויית ברירת המחדל שקולה ללוח שלהם —
  ממוין דחוף → תאריך → תיק, סימון ✓ בנגיעה אחת, גם במובייל.
- **מיתוג:** שם משרד, לוגו, צבעים — להפוך לקונפיגורציה (white-label).

### 3.3 חדש — צריך פיתוח

#### א. ספר אנשי קשר מקצועיים (המודול החדש המרכזי)

ישות `professional_contact` רב-שימושית:

- **סוגים:** בנקאי/ת (משויך לסניף), שמאי/ת, עו"ד / משרד עו"ד, סוכן ביטוח,
  חברת נדל"ן / יזם, מפנה
- **שדות:** שם, סוג, טלפונים, מייל, שיוך (בנק+סניף לשמאי/בנקאי), הערות
- **קישור לתיק:** תיק ↔ אנשי קשר בתפקיד (הבנקאית של התיק, השמאי של התיק,
  עו"ד מוכר, סוכן ביטוח, מפנה) — לשימוש חוזר במקום הקלדה מחדש
- שמאים: שיוך לרשימת הבנקים שמאשרים אותם

#### ב. רישום שמאויות (התשתית להמלצת השמאי)

על כל תיק עם שמאות: שמאי, בנק, תאריך שליחה, תאריך קבלה, שווי צפוי, שווי
בפועל, הערות. **כבר משלב א'** — כדי שבשלב ב' יהיה דאטה להמלצות
("לשמאי X לוקח בממוצע 6 ימים ומגיע ל-97% מהשווי הצפוי במזרחי").

#### ג. מעקב הפניות ודמי הפנייה

- שדה מפנה על התיק (מקושר לספר אנשי הקשר)
- הסכם דמי הפנייה: אין / סכום קבוע / אחוז
- מעקב תשלום דמי הפנייה (חיבור ל-`case-expenses` או `case-payouts` הקיימים)
- מסך רוחבי: כמה תיקים הפנה כל מפנה וכמה שולם לו

## 4. מה נשמר מהרגלי העבודה הקיימים

עקרון מנחה: המערכת מחליפה את הגיליון בלי לשבור את שגרת היום.

1. **לוח משימות מרוכז** ממוין דחוף → תאריך יעד — המסך הראשי של כל מטפל.
2. **הוספת משימה מהירה מתוך תיק** עם בחירת משויך + דחיפות בנגיעה
   (המקבילה של "טקסט + נקודות").
3. **תשלום = סכום + תאריך אוטומטי** — כמו שהסקריפט עושה היום.
4. **תצוגת תיק אחת שרואה הכל** — העמודה שלהם הייתה "כל התיק במבט אחד";
   כרטיס התיק צריך לתת את אותה תחושה.

## 5. שאלות פתוחות לפגישת האפיון

1. **צוות ותפקידים:** מאושר שהמשרד מעסיק כמה עובדים (בגיליון מזוהים שמעון
   ומנחם). למפות מי זה מי, מי מנהל, מי מטפל, יש מזכירות? אילו שדות חסויים
   למנהל בלבד (שכ"ט? דמי הפנייה?) — מערך ההרשאות הקונפיגורבילי הקיים
   רלוונטי במלואו.
2. **סטטוסים:** לעבור איתם על 12 השלבים — מה מתאים, מה לשנות בניסוח.
3. **מודל שכ"ט:** קבוע / אחוז / מדורג? כמה תשלומים בפועל? חשבוניות?
4. **דמי הפנייה:** איך נקבעים היום? האם המפנים ידעו שיש מעקב?
5. **מסמכים:** איפה חיים היום (מייל? דרייב?) — הנהלים מוטי-מייל מאוד.
   האם רוצים סנכרון Drive כמו אצל קופמן?
6. **נפחים:** כמה תיקים חדשים בחודש? כמה תיקים סגורים יש להיסטוריה?
7. **שפה:** הדאטה כולו עברית — האם ממשק אנגלית נדרש בכלל?
8. **הלוואות קבלן:** מופיעות כקטגוריה בגיליון — האם זה סוג תיק שונה עם
   תהליך שונה?
9. **מיגרציה:** האם מעבירים גם תיקים סגורים או רק את ~68 הפעילים?

## 6. מיגרציה מהאקסל

- הדאטה חצי-מובנה: שורות "זולגות", הכנסות/התחייבויות בטקסט חופשי
  ("תלוש אשה 11100"), טלפונים מרובים בתא אחד.
- **גישה:** ייבוא חד-פעמי בעזרת פרסור AI + מסך אימות ידני תיק-תיק
  (מודול `import` הקיים כבסיס). ~68 תיקים = היקף סביר לאימות ידני.
- משימות פתוחות מיובאות כ-tasks עם המשויך והדחיפות לפי הנקודות.
- שווה לתכנן את המיגרציה כך שהמשרד עובר במכה אחת (לא תקופת כפל מערכות ארוכה).
